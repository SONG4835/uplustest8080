# PRD.md — 요금제 추천·구독 서비스

> 작성 근거: 지금까지 인터뷰 답변, 도메인 스토리, 유저 스토리, screens.md.
> 인터뷰에서 말씀하지 않은 내용은 "미정"으로 표시했다. "제안"은 인터뷰에 없는 내 제안이다.

## 1. 목적

### 한 줄 정의
요금제 추천·구독 서비스는 청구금액이 오른 고객이 상담 연결이나 판매자 없이 요금제를 비교하고 직접 변경을 신청하는 모바일 웹 서비스다.

### 해결할 문제
1. 요금제를 바꾸려고 고객센터에 전화해도 상담사 연결이 지연되거나 음성안내만 나온다. (발생 빈도 수치: 미정)
2. 휴대폰을 구입한 개통점 판매자에게 문의하려 해도 판매자가 퇴사해서 연락할 곳이 없다. (발생 빈도 수치: 미정)
3. 앱에서 직접 바꾸려 해도 사용법이 익숙하지 않아 변경을 끝내지 못한다. 또한 가족결합 같은 다른 할인과 묶여 있으면 바꾼 뒤 실제 요금이 비슷해질까 불안해서 결정을 못 한다. (불안 부분은 전문가 추정이며 실제 고객 발언은 미확인)

## 2. 대상 사용자

### 유저 스토리
1. 고객으로서, 청구서 금액이 올라간 이유를 파악하기 위해 이번 달 청구 내용과 해지된 할인 프로그램을 확인하고 싶다.
2. 고객으로서, 상담 연결 지연이나 판매자 퇴사 같은 장벽 없이 요금제를 바꾸기 위해 앱에서 직접 변경 신청을 하고 싶다.
3. 고객으로서, 데이터양에 맞는 요금제를 고르기 위해 요금제별 기본 제공 데이터와 월 요금을 비교하고 싶다.
4. 고객으로서, 가족결합 같은 다른 할인이 줄어 요금이 비슷해지는 일을 피하기 위해 변경 전후의 실제 부담 요금을 확인하고 싶다.
5. 고객으로서, 앱 사용이 익숙하지 않아도 변경을 끝내기 위해 단계별 안내에 따라 신청을 완료하고 싶다.

### 사용자 상황
- 고객 A는 청구서를 열어 보고 할인 프로그램이 해지되어 전월보다 금액이 커진 것을 확인했다.
- 요금제를 바꾸려고 고객센터에 전화했지만 상담사 연결이 지연되고 음성안내만 나왔다.
- 휴대폰을 산 개통점 판매자에게 전화했지만 이미 퇴사한 상태였다.
- 앱에서 직접 바꾸려 했으나 사용법이 익숙하지 않아 끝내지 못했다.
- 이후 A가 요금제를 유지했는지, 다른 방법을 찾았는지는 미정이다.

## 3. 화면 목록

> screens.md의 화면 이름과 순서를 기준으로 하되, 유저 스토리에 맞게 "청구 확인"을 맨 앞에 추가하고 "구독 신청"을 "변경 신청"으로 바꿨다. (제안)

### 화면 구조

**청구 확인**
- 한 줄 역할: 이번 달·전월 청구액과 해지된 할인 프로그램을 보여주고 요금제 변경으로 이어준다.
- 해결하는 유저 스토리: 1

**요금제 목록**
- 한 줄 역할: 요금제의 데이터양과 월 요금을 비교하고 상세로 진입한다.
- 해결하는 유저 스토리: 3

**요금제 상세**
- 한 줄 역할: 선택한 요금제의 제공 사항과 변경 전후 실제 부담 요금을 확인하고 신청을 시작한다.
- 해결하는 유저 스토리: 3, 4

**변경 신청** (신청 흐름)
- 한 줄 역할: 선택한 요금제를 확인하고 신청 정보와 필수 동의를 입력해 변경을 신청한다.
- 해결하는 유저 스토리: 2, 4, 5

**신청 완료**
- 한 줄 역할: 변경 신청이 끝났음을 알리고 신청 내역을 보여준다.
- 해결하는 유저 스토리: 2, 5

### 주요 흐름
- 청구 확인 → 요금제 목록 → 요금제 상세 → 변경 신청 → 신청 완료
- 되돌아가기: 요금제 목록 → 청구 확인
- 되돌아가기: 요금제 상세 → 요금제 목록
- 되돌아가기: 변경 신청 → 요금제 상세
- 신청 완료의 이동 목적지(뒤로 가기, 버튼): 미정

## 4. 화면별 기능

### 4-1. 청구 확인
필수 기능:
1. 이번 달 청구액과 전월 청구액을 나란히 표시하고, 두 금액의 차이를 증감액으로 표시한다. 기본 상태는 이번 달 기준이다.
2. 해지된 할인 프로그램이 있으면 이름을 목록으로 표시한다. 없으면 "해지된 할인이 없어요"를 표시한다. (문구는 제안)
3. "요금제 바꾸기" 버튼을 누르면 요금제 목록으로 이동한다.

오류 상황과 안내 문구: 입력 없음. 청구 정보 조회 실패 시 처리와 문구는 미정이다.
청구 정보를 어디서 가져오는지도 미정이다.

### 4-2. 요금제 목록
필수 기능:
1. 요금제 카드에 이름 · 월 요금 · 데이터량 · "자세히" 버튼을 표시하고, 기본 정렬은 추천순이다.
2. 추천 배지는 카드 1개에만 표시한다.
3. 기존 월 요금과 할인율이 있는 요금제는 함께 표시한다.
4. "자세히" 버튼을 누르면 해당 요금제의 상세 화면으로 이동한다.
5. 상단에 FilterChip을 표시한다. 기본은 "데이터 많이"가 선택된 상태이고, 선택 방식과 필터 항목은 미정이다. (screens.md의 "구독 포함" 등은 인터뷰에 없는 내용)

오류 상황과 안내 문구: 입력 없음. 필터 결과 없음, 목록 조회 실패 시 문구는 미정이다.

### 4-3. 요금제 상세
필수 기능:
1. 요금제 이름 · 월 요금 · 기존 월 요금 · 할인율 · 데이터 · 통화 · 문자를 표시한다.
2. 변경 전후 실제 부담 요금을 비교해 표시한다. 가족결합 등 기존 할인의 유지 여부도 함께 표시한다. 계산 방식과 데이터 출처는 미정이다.
3. 하단 고정 영역에 월 납부 금액과 "변경 신청하기" 버튼을 표시한다. 버튼을 누르면 선택한 요금제를 유지한 채 변경 신청 화면으로 이동한다.
4. 뒤로 가기를 누르면 요금제 목록으로 돌아간다.

오류 상황과 안내 문구: 입력 없음. 존재하지 않는 요금제 id로 진입했을 때의 처리는 미정이다.

### 4-4. 변경 신청
필수 기능:
1. 선택한 요금제 이름과 월 요금을 상단에 표시한다.
2. 이름과 휴대폰 번호를 입력받는다. 기본 상태는 빈 값이다. (고객이 이미 가입된 상태라 직접 입력이 필요한지는 미정)
3. "[필수] 개인정보 수집·이용에 동의합니다" 체크박스를 표시한다. 기본 상태는 해제다.
4. 필수 항목이 모두 채워지고 동의가 선택된 경우에만 "신청하기" 버튼을 누를 수 있다. 성공하면 신청 완료 화면으로 이동한다.
5. 신청 전에 선택한 요금제와 변경 내용을 한 번 더 확인하게 한다. (제안, 앱이 익숙하지 않은 고객을 위한 것)
6. 뒤로 가기를 누르면 해당 요금제 상세로 돌아간다. 입력값 유지 여부는 미정이다.

오류 상황과 안내 문구 (문구는 모두 제안):
- 이름이 비어 있음: "이름을 입력해 주세요"
- 휴대폰 번호가 비어 있거나 형식이 틀림: "휴대폰 번호를 확인해 주세요"
- 필수 동의 미선택: "개인정보 수집·이용에 동의해 주세요"
- 신청 실패: 안내 문구와 화면 유지 여부는 미정
- 중복 제출 방지 정책: 미정

### 4-5. 신청 완료
필수 기능:
1. "변경 신청이 완료됐어요" 안내와 완료 아이콘을 표시한다.
2. 신청 내역에 신청 번호 · 요금제 · 월 요금 · 신청 일시 · 신청자를 표시한다. 신청자 이름과 휴대폰 번호는 일부를 가려서 표시한다.
3. 변경이 적용되는 시점을 표시한다. 적용 시점 정보는 미정이다.
4. 하단 버튼의 이동 목적지는 미정이다. (screens.md의 "요금제 더 보기"는 변경 완료 후 맞지 않을 수 있음)

오류 상황과 안내 문구: 입력 없음. 신청 내역 없이 직접 진입하거나 새로고침했을 때의 처리는 미정이다.

### 요금제 데이터
실습용 가상 데이터이며 실제 요금이 아니다. screens.md 템플릿의 예시 값을 가져왔다.

| id | 이름 | 월 요금 | 데이터 | 한 줄 설명 |
|---|---|---|---|---|
| p01 | 넉넉 무제한 | 85,000원 | 무제한 | 데이터·통화 무제한, 24개월 할인 프로모션 |
| p02 | 스탠다드 110 | 69,000원 | 110GB | 데이터 110GB, 통화 무제한 |
| p03 | 라이트 30 | 49,000원 | 30GB | 데이터 30GB, 통화 무제한 |
| p04 | 슬림 10 | 39,000원 | 10GB | 데이터 10GB, 통화 무제한 |

### 어기면 안 되는 것
1. 추천 배지는 요금제 목록에 1개만 보인다.
2. 요금제 목록의 모든 카드에 이름 · 월 요금 · 데이터량 · "자세히" 버튼이 보인다.
3. 필수 동의를 선택하지 않으면 "신청하기" 버튼으로 신청이 진행되지 않는다.
4. 신청 완료 화면에 신청자 이름과 휴대폰 번호 전체가 그대로 보이지 않는다.
5. 변경 신청 화면에는 선택한 요금제의 이름과 월 요금이 보인다.
6. 전체 화면 수는 5개이고 신청 흐름은 1개다.

## 5. 데이터

```
Subscription (변경 신청)
  id        신청 번호
  name      신청자 이름
  phone     신청자 휴대폰 번호
  plan_id   선택한 요금제 id (p01~p04)
```

제안: 아래 항목은 인터뷰에 없어서 필요 여부를 확인해야 한다.
- created_at (신청 일시): 신청 완료 화면에 표시되므로 필요해 보임
- 변경 전 요금제와 청구 정보: 청구 확인, 변경 전후 비교에 필요하지만 출처 미정
- 가족결합 등 결합 할인 정보: 출처와 계산 방식 미정

## 6. 범위 밖

### 이번에 안 함
- 실제 청구 시스템·결합 할인 시스템 연동 (가상 데이터로 대체)
- 상담 연결 화면, 판매자 연락 같은 보조 경로
- 로딩·빈·에러 화면의 세부 디자인 (미정 항목)
- 결제, 본인 인증, 로그인

### 나중에 붙일 것
- 변경 전후 실제 부담 요금의 정확한 계산
- 고객센터 상담 연결 대체 경로
- 변경 후 청구액·혜택 확인 (인터뷰의 "바꾸길 잘했다/괜히 바꿨다" 평가 단계)
